# 测试计划与验收标准

此文件列出计划和判定标准，不表示所有项目已执行。实际结果以执行报告、日志和截图为准。主验证平台为鲁班猫 1 的 Linux / aarch64，文件目录应位于支持稀疏文件的文件系统。

2026-10-16 实际执行结果：真实鲁班猫在 ext4 上完成原生构建，现有 16 个自动测试方法全部通过，0 失败、0 错误、0 跳过，包含 3 个故障注入方法；额外空洞与真实 SIGINT 恢复演示也通过。20 个计划场景并不因此自动变为 20 项独立执行结果，具体覆盖和原始输出见 [板端实测报告](board-test-report.md)。四组原生终端截图已齐备，见 [截图索引](board-screenshots.md)。

## 验收场景（含自动与人工计划）

下表是 20 个验收场景，包含自动测试和人工观察，不等于自动测试方法数量。`tests/test_cli.py` 当前有 16 个自动测试方法，一个方法可以覆盖多个场景；具体是否执行、通过或跳过，以运行报告为准。

在项目根目录执行 `make check`。测试应在临时目录创建自己的文件，不覆盖用户文件；若测试失败，报告名称、退出码、stdout / stderr 和最小复现。可用 `make sanitize` 补充内存及未定义行为检查，但不得用其替代真实板端功能测试。

| 编号 | 测试 | 预期与验收依据 |
|---|---|---|
| T01 | create 131072 和 1048576 字节 | 大小精确；未写区读为零；支持稀疏的测试文件系统上实际分配明显小于逻辑大小 |
| T02 | create 131071、负数、小数、带后缀、超范围整数 | 非零退出，不当作有效目标创建 |
| T03 | 同路径再次 create | 拒绝覆盖，原内容及大小保持不变 |
| T04 | 中部写入 HELLO | 指定 5 字节正确，前后内容不变，逻辑大小不变；空间分配按块变化 |
| T05 | 从 EOF 写空字符串、从 EOF 写非空串、越界偏移 | 空串可合法无改动；非空和越界拒绝，大小不增加 |
| T06 | resume 无状态目标 | 从 0 开始，最终偏移等于大小，verify 成功 |
| T07 | resume 中途 SIGINT | 输出 interrupted，返回 130，保存 0 < done < size；主循环完成当前块后退出 |
| T08 | T07 后再次 resume | resume_from 等于保存值；结束后逐字节比较确定性数据 |
| T09 | 多次中断和恢复，尾部不足一个块 | 每次有效进度单调增加；最后短块正确；总长度保持不变 |
| T10 | 完成后再次 resume | 从 EOF 开始直接 complete，内容不变 |
| T11 | 状态缺损、尾部垃圾、超长、越界偏移、错误身份 | 拒绝恢复，不根据猜测跳过数据 |
| T12 | resume 状态存在时执行 write | 拒绝，已完成数据保持不变 |
| T13 | chunk 0、65537；delay 60001 | 拒绝；合法边界 1、65536、0、60000 可解析；长延时无需无意义等待 |
| T14 | resume 期间并发修改或查询命令 | 协作锁冲突时快速报 busy，避免同时修改 |
| T15 | 符号链接、目录、FIFO 等异常目标 | 不跟随最终目标符号链接，不修改非普通文件；FIFO 不应无限阻塞 |
| T16 | 篡改已完成文件后 verify | 准确报出首个错误偏移并非零退出 |
| T17 | 状态与目标的绑定检查 | 另一目标复制来的状态不能冒认当前目标，即便大小相同 |
| T18 | 完成目标创建硬链接，再通过别名 write/resume | 所有修改操作拒绝多硬链接目标，原内容不变；只读操作可执行 |
| T19 | 同 inode、同大小的已完成前缀被原地损坏 | resume 在写入前验证前缀并报错，不盲信已完成偏移 |
| T20 | 状态字段为负数、超 uint64、缺末尾换行 | 严格拒绝畸形记录，不能被无符号格式转换默许 |

空洞判定要把内容与物理分配分开：读取为零不证明没有分配磁盘块，实际占用应查看 `st_blocks`。定点写入测试也应读取整个逻辑范围或充分覆盖前后区域，避免只验证写入位置而漏掉其他数据损坏。

## 板端人工验收与截图

按 `docs/class-share.md` 的独立临时目录执行。建议截图同时显示命令、输出、终端中的主机提示和环境信息，保持文字清晰。截图不要包含密码、私钥或 API 密钥。

| 截图 | 必须展示的事实 |
|---|---|
| 01 环境和编译 | uname、aarch64、编译成功、自动测试实际结果 |
| 02 空洞和定点写入 | create 后逻辑大小与块占用，写入后的块占用及局部十六进制内容 |
| 03 中断保存 | Ctrl+C 后 interrupted，状态中保存的中间偏移 |
| 04 恢复和校验 | resume_from 等于断点，最终 verify 成功和 100% 进度 |

`status` 的 `space_percent` 不应强制等于 `progress_percent`：实际分配以文件系统块计，进度以已同步的连续字节计。完全写入后的占用也不必精确等于 100%，取决于文件系统及其分配策略。

## 未纳入已通过结论的项目

突然断电后的恢复、故障存储、绕过协作锁的并发篡改、真实 HTTP 的 Range/ETag/服务端变化及多线程乱序下载，均需要额外设计和验证。此作业不能仅依据 Ctrl+C 测试声称这些情况已获保证。
