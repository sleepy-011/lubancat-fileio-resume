程序以 Linux 文件 IO 和系统调用为核心，使用可重复生成的本地数据流模拟下载，方便独立验证结果。

三、功能实现
1. create：新建逻辑大小至少为 131072 字节（128 KiB）的空洞文件，使用 ftruncate 设置长度，不通过循环写零填充整个文件。
2. write：使用 lseek 和 write 在指定偏移写入数据，检查写入边界，不改变其余区域和逻辑长度。
3. resume：单独记录连续完成偏移，数据同步成功后才更新状态；中断后可从保存位置继续。
4. status：输出逻辑大小、实际分配块数、实际占用字节数、空间占比及续传进度。
5. verify：按照确定性数据规则逐字节检查整个文件，确认内容没有遗漏、重复或错位。

四、代码审查与优化
保留了初版代码，并针对实际发现的问题完成修复：
1. 非普通文件可能导致打开操作阻塞：改为非阻塞打开，再检查目标是否为普通文件。
2. 状态记录解析不严格：检查十进制字段、数值范围、分隔符、终止换行和目标文件身份。
3. 硬链接别名可能绕过手工写入限制：修改操作拒绝存在硬链接别名的目标文件。
4. 仅凭完成偏移不能证明数据正确：续传前校验已完成前缀，发现损坏即拒绝继续。
同时实现部分写入和 EINTR 重试、协作式文件锁、数据同步、临时状态文件原子替换等处理。
初版在真实板端回归中出现 7 个失败断言或子用例、1 个超时错误，涉及上述四类问题；修复版对应测试全部通过。

六、关键功能实测
创建 1 MiB 文件后，逻辑大小为 1048576 字节，初始实际占用为 0 字节。
在偏移 65536 处定点写入后，逻辑长度保持不变，实际分配为 8 个 512 字节单位，即 4096 字节。
向实际续传进程发送 SIGINT（与 Ctrl+C 相同的信号）后，保存完成偏移 4096，程序返回 130。
再次启动续传时，resume_from 为 4096，与保存的断点一致。
续传结束后，完成偏移为 1048576，verify 输出 result=verified，进度为 100%。
