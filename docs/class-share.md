## 讲稿

**0:00—0:40 任务与范围。**

我的项目是一个基于 Linux 文件 IO 的空洞文件断点续传模拟器，运行目标是鲁班猫 1。它支持创建空洞文件、定点写入、保存进度后继续和空间占用统计。为了让结果可重复检查，数据由固定规则生成：第 n 个字节等于 1 加 n 对 251 取余。这次实现聚焦文件 IO；没有接入真实 HTTP 服务。

**0:40—1:20 空洞原理与演示。**

首先创建 1 MiB 文件。逻辑大小在创建时已经达到 1 MiB，但不需要把整个文件写满。未写区域读出来是零，实际分配要看 stat 中的块数。接着在 65536 的偏移写入 HELLO，只改变这 5 个字节。磁盘分配是按块进行，所以实际占用增加通常比 5 字节大。空间占比使用 st_blocks 乘以 512 再除以逻辑大小，不能用最佳 IO 块大小代替 512。

**1:20—2:30 中断与恢复演示。**

我再用一个新文件演示续传，避免和手工文本混在一起。程序每次写一块，先确认数据同步，再更新独立的状态文件。按 Ctrl+C 后，信号处理函数只设置退出标志，主循环完成当前块的检查点后返回终端。现在查看保存的偏移，再次运行时 resume_from 应等于它。恢复完成后，我进行逐字节验证，确认没有遗漏或错位。文件创建时大小已经完整，因此不能用文件大小推断下载进度。

**2:30—3:25 AI 审查与优化。**

AI 参与了代码、测试和文档工作。独立审查发现 FIFO 打开会阻塞、状态解析不够严格、硬链接别名绕过写入限制等实际问题，分别采用非阻塞打开、严格字段解析和修改前检查链接数修复。恢复前还增加了已完成前缀的内容校验，避免文件损坏后仍报完成。16 项板端测试已全部通过，包括这些问题的回归和 3 项故障注入。本次使用 GPT/Codex，保留了 8 条真实独立指令、对应产物和采纳判断；使用记录与初版、修复差异均可核对。原图所列 DeepSeek 已在材料中注明为工具替代，没有冒称调用。

**3:25—4:00 总结边界与取舍。**

本项目的关键是区分逻辑大小、实际占用和完成偏移。每块同步会影响速度，但能让检查点的顺序容易解释和验证。当前验证针对 Ctrl+C 和实际报告中列出的测试，不能据此保证突然断电恢复，也不能防止其他不遵守锁的程序篡改文件。代码、测试、文档和真实运行材料可以相互对应。

## 演示命令

先进入项目根目录完成 `make`，再执行。为保持节奏，可以在课前编译并保留结果；演示目录仍在现场新建。

```sh
uname -m
demo_dir=$(mktemp -d ./class-demo.XXXXXX)
printf '演示目录：%s\n' "$demo_dir"

./sparse-dl create "$demo_dir/holes.bin" 1048576
./sparse-dl status "$demo_dir/holes.bin"
./sparse-dl write "$demo_dir/holes.bin" 65536 HELLO
./sparse-dl status "$demo_dir/holes.bin"
od -An -tx1 -j 65532 -N 13 "$demo_dir/holes.bin"

./sparse-dl create "$demo_dir/resume.bin" 1048576
./sparse-dl resume "$demo_dir/resume.bin" 4096 100
```

等待约 2 秒，按 Ctrl+C；看到终端提示符后继续：

```sh
./sparse-dl status "$demo_dir/resume.bin"
cat "$demo_dir/resume.bin.state"
./sparse-dl resume "$demo_dir/resume.bin" 65536
./sparse-dl verify "$demo_dir/resume.bin"
./sparse-dl status "$demo_dir/resume.bin"
```

若新文件名冲突或实验中断，不要删除未知文件，重新建立一个演示目录再开始。若网络连接不稳定，可在板端本地终端演示，或使用本次实际保存的日志与截图说明；必须区分现场结果和之前记录。

## 答辩准备

- **为什么读到零还要看块数？** 零既可能来自空洞，也可能来自实际写入的零数据；分配占用用块数判断。
- **为什么不只保存文件大小？** 空洞在创建时已有完整逻辑大小，进度需要独立记录。
- **为什么先同步数据再记录状态？** 避免状态领先而跳过尚未持久化的数据；落后的检查点可以重写。
- **为什么只需要一个偏移？** 目前按顺序写入，已完成区域是一个连续前缀；乱序下载需要区间表等结构。
- **最后一个块不足指定长度怎么办？** 写入长度取剩余字节数和块大小的较小值。
- **为什么有状态后禁止手工 write？** 手工修改可能破坏“已完成前缀”的含义；分开演示更清楚。
- **能否保证掉电？** 当前有同步和原子检查点设计，但未做硬件掉电验证，不宣称全面保证。
